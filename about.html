关于 Whither

一个让 AI Agent 帮你规划旅行的实验性项目。

为什么做这个？

规划旅行很烦人——要刷攻略、查天气、看车次、比价格、排优先级。这些信息散落在十几个 App 里，脑子都记不过来。

Whither 试了一个不同的思路：让 AI Agent 主动去"找"这些信息，而不是让用户去一个一个 App 里翻。它背后接的是真实的数据源——12306 车次、高德交通、Tavily 搜索、4288 条攻略知识库——并且会用工具之间的结果相互印证。

项目名 "Whither" 来自莎士比亚的台词 "Whither thou goest, I will go"——意思是"你去哪我去哪"。我们希望 Whither 能真正理解一个旅行者想去的地方，而不只是给一些通用的模板。

🎯 定位

消费级中文旅行规划 Agent。不是企业 SaaS，不收费，只把功能做扎实。

🧠 设计理念

工具优先而非模型优先。RAG + MCP 比纯 prompt 更可靠，真实数据比想象数据更有价值。

📋 覆盖范围

国内 107 座热门城市，4288 条精选攻略，持续更新。

技术选型理由

为什么选了这些，而不是那些。

LangGraph 而不是 ReAct Agent

LangGraph 能精细控制状态机，工具调用有明确的节点边界，比 ReAct 循环更可控、更容易调试。

FastAPI + SSE 而不是 WebSocket

SSE 是 HTTP 标准协议，反向代理零配置即可工作，比 WebSocket 更轻量。

MCP Protocol 统一工具

MCP 让工具即插即用。接新数据源（航班、美食）只需要写一个 MCP server，不用改主代码。

DashScope qwen3.7-text-embedding

默认 1024 维，本地 bge-m3 开发 / DashScope 部署无缝切换。有免费额度。

原生 HTML/CSS/JS 前端

无框架、无构建、无依赖。Netlify 零配置部署，用户"查看源代码"也能看懂。

Dockerfile 强制构建

和本地环境一致，不用和 Railway 基础镜像里预装的 Python 版本打架。
