架构概览

Whither 采用 LangGraph 构建 Agent 状态机，由 FastAPI + SSE 对外提供流式对话接口。前端是纯静态单文件应用，后端通过 MCP 协议 接入外部工具（12306、高德、Tavily 等）。

知识库使用 DashScope qwen3.7-text-embedding 对 4288 条攻略做向量化，查询时内存矩阵检索（零 SQL），1024 维与 bge-m3 兼容。

技术栈

模块技术
Agent 编排LangGraph + LangChain
后端框架FastAPI + uvicorn + SSE
向量化 / RAGDashScope qwen3.7-text-embedding + SQLite (bge-m3 兼容)
LLMOpenAI 协议（ChatAnywhere 等）
工具调用MCP Protocol（12306 / 高德 / Tavily）
PDF 生成Playwright Chromium
会话持久化Neon (PostgreSQL) + langgraph-checkpoint
前端原生 HTML/CSS/JS（无框架）

本地部署（推荐先跑通这个）

环境要求

  • Python 3.11+（推荐 3.11，最新稳定）
  • Node.js 20+（12306 MCP 通过 npx 启动）
  • Docker Desktop 可选（一键构建）

步骤 1：克隆仓库

git clone https://github.com/yijuntuqi/Whither.git
cd Whither

步骤 2：创建虚拟环境 + 安装依赖

python -m venv .venv
# Windows PowerShell
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements-runtime.txt
playwright install chromium

步骤 3：配置环境变量

cp .env.example .env   # 或 Windows copy .env.example .env

然后编辑 .env，填入你的 Key。最少要填：

LLM_PROVIDER=openai
OPENAI_API_KEY=sk-xxxxxxx
OPENAI_API_BASE=https://api.chatanywhere.tech/v1

EMBEDDING_PROVIDER=dashscope
DASHSCOPE_API_KEY=sk-ws-xxxxxxxxxxxxxxxxx
DASHSCOPE_EMBED_MODEL=qwen3.7-text-embedding

TAVILY_API_KEY=tvly-xxxxxxx
AMAP_MCP_URL=https://mcp.amap.com/mcp?key=你的高德Key

步骤 4：启动后端

python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload

打开 http://localhost:8000，就能看到 Whither 前端。

（可选）Docker 方式

# 国内构建加速
docker build --build-arg USE_TUNA=1 -t whither:latest .

# 本地运行
docker run -p 8000:8000 --env-file .env whither:latest

Railway 后端部署

⚠️ 重要：Railway 构建成功 ≠ 环境变量已注入
在 Railway 上你需要分别配置 Service Variables（不是 Project Variables）。构建成功后进入服务 → Variables 标签 → 逐个添加下面的变量。

1. 新建 Railway Project → Deploy from GitHub → 选择 Whither 仓库

2. Deployments 标签看到 Build 成功后，进 Variables 标签，添加：

KeyValue
EMBEDDING_PROVIDERdashscope
DASHSCOPE_API_KEY你的 DashScope Key
DASHSCOPE_EMBED_MODELqwen3.7-text-embedding
LLM_PROVIDERopenai
OPENAI_API_KEY你的 ChatAnywhere Key
OPENAI_API_BASEhttps://api.chatanywhere.tech/v1
TAVILY_API_KEY你的 Tavily Key
AMAP_MCP_URL你的高德 MCP URL

3. 加完变量会自动触发重新部署。成功后 Settings → Networking → Generate Domain 拿到域名（如 whither-production.up.railway.app）。

4. 打开域名确认 200，去 Railway 的 Console 标签执行 echo $OPENAI_API_KEY，能打印出 Key 就说明注入成功。

Netlify 前端部署

前端是独立仓库 whither-web（纯静态 HTML/CSS，无 Python 依赖）。

1. whither-web 仓库 → Netlify → Add new site → Import existing project

2. Netlify 自动识别 netlify.toml，直接 Deploy 即可（没有任何 build step）

3. 部署成功后打开 Netlify 域名 → 右上角 ⚙ 后端 → 粘贴 Railway 域名 → 保存

FAQ

Q: Railway 上 ChatOpenAI 初始化失败，说没有 API Key？

这是 Railway 变量注入位置问题。检查：

  • 变量是加在 Service > Variables（不是 Project Variables）
  • Console 里 echo $OPENAI_API_KEY 能打印出值
  • 加完变量后触发了重新部署

Q: Netlify 部署报错 Python 3.14 + unstructured 不兼容？

这个问题只会在你把后端仓库（含 requirements.txt）当前端仓库部署时出现。请使用 独立前端仓库 whither-web（纯静态，没有任何 Python 文件）。

Q: Embedding 模型名填什么？

DASHSCOPE_EMBED_MODEL=qwen3.7-text-embedding。默认维度 1024，与 rag.sqlite 里的 bge-m3 向量兼容。

Q: 高德 MCP 留空会怎么样？

系统会自动降级为"建议现场导航"，不影响基本功能。

Q: 本地 ollama 和 DashScope 可以混用吗？

可以。设置 EMBEDDING_PROVIDER=ollama 走本地模型，DASHSCOPE 走云 API。LLM 也是同理。

Q: rag.sqlite 怎么更新？

用 scripts/ 下的爬虫 + 向量化脚本重新生成，然后替换 data/rag.sqlite 即可。
